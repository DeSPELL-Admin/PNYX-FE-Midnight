# CLAUDE.md

Guidance for Claude Code when working in `midnight/PNYX-FE` — the Midnight (Lace) port of `../../PNYX-FE`.

## What changed from the legacy EVM/wagmi stack

The legacy EVM/wagmi wallet, chain, and auth stack was removed and replaced with Midnight. Design, routes,
components, API client, and game logic are retained.

| Legacy EVM/wagmi stack (removed)                  | Midnight                                                                 |
| ------------------------------------------------ | ------------------------------------------------------------------------ |
| `WagmiProvider` + RainbowKit + Startale connector | `components/providers/MidnightProvider.tsx` (Lace via DApp connector 4.x) |
| `useAccount/useChainId/useDisconnect` from wagmi  | same names from `~/hooks/wallet` (adapter over `useMidnight()`)          |
| SIWE (`lib/auth/siwe.ts`, `viem/siwe`)            | `lib/auth/midnightAuth.ts` + Lace `signData` → `POST /auth/midnight/verify` |
| `useContractWriteWithReceipt` + ABI               | `hooks/contract/useFinalizeTournament.ts` → midnight-js `callTx.finalizeTournament` (ZK proof in browser) |
| BE EIP-712 signature                              | BE inserts an eligibility leaf on-chain and returns `{ point, deadline }` |
| `lib/chains.ts` (legacy EVM networks)             | single Midnight network + **synthetic chainId** (`lib/midnight/config.ts`) |
| ENS, NetworkSwitcher (switch chains)              | removed / replaced by an info panel                                       |

Repository scope rule from the original CLAUDE.md still applies: write only inside this repo.

## Finalize flow (Result.tsx)

1. no consent choice — every submitted vote is sellable (single-product model)
2. `POST /chains/:chainId/signatures/tournament-finalize { tournamentId, tournamentData, userPk }` → BE runs
   `grantEligibility(leaf)` and returns `{ point, deadline, txId, segment }`
3. browser proves `finalizeTournament{16|32|64}(tid, point, deadline, bracket, segment)` (9.6/19/19 MB prover
   key from `/zk/TournamentFinalizer`, ~30 s measured) and Lace balances/submits. `bracket` is the LWA
   final array (`finalArray`, `[0]`=champion); the circuit publishes 7 match counters on-chain and the
   grant leaf pins `bracketHash`, so only the exact granted bracket can be submitted. **16/32/64 rounds** — the hook dispatches to `finalizeTournament16|32|64` by `bracket.length`. **B-design**: the bracket is sealed inside the commitment (`bracketHash` in VoteRow) — nothing about the picks is public on-chain; escrow now carries the raw `bracket` so a buyer can re-derive and verify it.
4. always → `POST /chains/:chainId/escrow { tournamentId, itemId, segment, salt, txId }`

## Backend contract this FE expects (PNYX-BE work, SPEC §6.2)

- `GET /auth/nonce` (unchanged) · `POST /auth/midnight/verify { message, signature, verifyingKey }` → cookie session
- `POST /chains/:chainId/signatures/tournament-finalize` body now includes `userPk`; response `{ exists, txId, point, deadline, segment }`
- `POST /chains/:chainId/escrow` · `POST /chains/:chainId/midnight/finalize-confirm { tournamentId, txId }`
- `POST /auth/midnight/verify` body is `{ message, signedData, signature, verifyingKey }` (`signedData` = Lace `Signature.data`)
- `chainId` for Midnight preprod is the synthetic `99101` (`MIDNIGHT_CHAIN_IDS`)

## Gotchas

- Never import midnight-js / compact-runtime in server components — `MidnightProvider` is `dynamic(..., { ssr: false })`.
- `userSecret` is per browser + address. Clearing it makes the same wallet look like a new user, but the
  on-chain nullifier is already spent → re-vote fails. `clearWalletStorage()` deliberately keeps it.
- Lace must be on the same network as `NEXT_PUBLIC_MIDNIGHT_NETWORK`; `connectWallet()` throws otherwise.
- If the wallet has no proof server configured, `NEXT_PUBLIC_MIDNIGHT_PROOF_SERVER_URL` is used (demo).
- `@midnight-ntwrk/onchain-runtime-v3` is pinned to 3.0.0 (same reason as in PNYX-Contract: two WASM copies break).

## Data market (`/market`, hackathon)

- `/market` lists escrow-backed tournaments (BE `/chains/:id/market/products`); Buy runs
  `useBuyDataset`: createOrder → Lace `makeTransfer` (tNIGHT to `payTo`, `tokenTypeRaw` verbatim from
  BE, `makeTransfer` does NOT submit — call `api.submitTransaction(tx)` then extract the txId with
  `Transaction.deserialize(...).identifiers()[0]`) → `pay` → route to `/market/orders/{orderId}`.
- `/market/orders/[id]` polls `useOrder` (3 s, stops on FULFILLED/FAILED) and renders the stage
  timeline; on FULFILLED it loads `VerifyPanel` via `dynamic(..., { ssr:false })` (WASM).
- `VerifyPanel` verifies WITHOUT trusting the server: downloads the dataset blob, then checks
  sha256(bytes) == on-chain `License.datasetHash`, rowCount == sampleAtSale (FULL/PARTIAL),
  specHash == `querySpecHash`, sha256(wallet address) == `buyerPk`, and per-row
  `voteCommitment` membership — all through `src/lib/midnight/license.ts`, which reads the ledger
  wallet-free via `indexerPublicDataProvider` (call `setNetworkId()` FIRST or address decoding breaks).
- Prices are atomic units as strings end-to-end (1 tNIGHT = 1e6 units); the FE only formats, never
  converts for the transfer value.
